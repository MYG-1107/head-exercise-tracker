# Search visibility setup

## What this release improves

- Clear, distinct title and meta description on each public page.
- Self-referencing canonical URLs and standard social-sharing metadata.
- A robots.txt file and sitemap listing only canonical, useful HTML pages.
- Normal HTML links between the tracker, guide, privacy and safety pages.
- Original, visible content that explains the tool and its limitations.
- Software/application metadata that describes the product without medical-result claims.

## What to do after publishing

1. Open Google Search Console and add the URL-prefix property: `https://myg-1107.github.io/head-exercise-tracker/`.
2. Complete the verification method Google offers for this property. If using a verification meta tag, add Google's exact tag to the `<head>` of `index.html` and commit it.
3. In Search Console, submit `https://myg-1107.github.io/head-exercise-tracker/sitemap.xml`.
4. Use URL Inspection for the home page and the guide page; request indexing if eligible. Check Pages/Indexing and Core Web Vitals reports over time.
5. Add the site to Bing Webmaster Tools and submit the same sitemap.
6. Share the product honestly where it is genuinely useful and seek relevant links from real users, accessibility communities or software directories. Do not buy links, generate fake reviews, or publish near-duplicate keyword pages.
7. Review Search Console queries and user feedback monthly. Improve pages based on actual impressions, click-through rate and usability rather than adding keywords everywhere.

## Ranking expectation

No developer can guarantee a first-place listing or a fixed search position. Search engines decide indexing and rankings, which also depend on competition, relevance, site reputation, links, user satisfaction and time. The purpose of this work is to remove technical obstacles and make the site accurately understandable and useful—not to promise a ranking.
